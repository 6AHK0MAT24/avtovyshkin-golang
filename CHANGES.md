# Изменения для режима разработки с Hot Reload

## 📋 Что было сделано

### 1. Созданы новые файлы

#### Docker конфигурация
- `docker-compose.dev.yml` - конфигурация только для PostgreSQL (без backend и frontend)

#### Скрипты запуска
- `start-dev.ps1` - запуск PostgreSQL в Docker
- `stop-dev.ps1` - остановка PostgreSQL
- Обновлен `start-backend.ps1` - теперь использует air для hot reload

#### Конфигурация Hot Reload
- `backend/drivers-microservice/.air.toml` - конфигурация air для автоматического перезапуска
- `backend/drivers-microservice/tmp/` - директория для временных файлов сборки

#### Документация
- `DEV_MODE.md` - подробная документация режима разработки
- `QUICKSTART.md` - быстрый старт за 3 шага

### 2. Обновлены существующие файлы

#### Конфигурация
- `.env` - изменен `POSTGRES_HOST` с `postgres` на `localhost` для локального подключения
- `.gitignore` - добавлены исключения для `tmp/` и `build-errors.log`

#### Документация
- `README.md` - добавлен раздел о рекомендуемом режиме разработки
- `START.md` - обновлена информация о скриптах запуска

## 🔄 Как это работает

### До изменений
- Backend запускался в Docker контейнере
- Изменения требовали пересборки контейнера
- Медленный цикл разработки

### После изменений
- PostgreSQL в Docker (изолирован и управляем)
- Backend запускается локально с hot reload
- Изменения применяются автоматически за 1-2 секунды
- Быстрый цикл разработки

## 🚀 Использование

### Запуск
```powershell
# 1. PostgreSQL в Docker
.\start-dev.ps1

# 2. Backend с hot reload (в новом терминале)
.\start-backend.ps1

# 3. Frontend (в новом терминале)
.\start-frontend.ps1
```

### Остановка
```powershell
# PostgreSQL
.\stop-dev.ps1

# Backend и frontend - Ctrl+C в соответствующих терминалах
```

## ✅ Преимущества

1. **Быстрый цикл разработки** - изменения применяются автоматически
2. **Полная отладка** - доступ к логам и отладчику
3. **Изолированная база** - PostgreSQL в Docker
4. **Простота** - минимум настроек, максимум удобства
5. **Гибкость** - можно использовать как старый, так и новый режим

## 📝 Примечания

- Старый режим (все в Docker) все еще доступен через `docker-compose up`
- Новый режим рекомендуется для локальной разработки
- Для production используйте `docker-compose --profile production up`
